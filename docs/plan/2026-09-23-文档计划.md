## 二、开发任务文档 SOP

### `DEV_WORKFLOW.md`

记录每次开发的强制流程：

1. 从 `main` 同步代码。
2. 切换或创建 `develop` 分支。
3. 创建对应的任务文档。
4. 记录现状、目标、范围和验收标准。
5. 实施代码或数据库变更。
6. 执行类型检查、构建和页面验证。
7. 更新 Roadmap 的功能状态。
8. 判断是否影响用户操作流程。
9. 如果影响流程，同步更新 `USER_MANUAL.md` 和对应截图。
10. 推送 `develop`，验证 Vercel Preview。
11. 创建 Pull Request 合并到 `main`。
12. 更新 `CHANGELOG.md` 和任务文档的发布记录。

### 当前功能手册重点

- 明确解释“豆种档案”和“购买批次”的区别。
- 明确说明同一支咖啡豆再次购买时，不新建豆种，而是新建批次。
- 明确说明没有豆种时不能直接创建批次。
- 明确说明只有 `ready` 或 `in_use` 批次可以记录冲煮。
- 明确说明冲煮记录会自动扣减库存。
- 明确说明编辑或删除冲煮是否会回滚库存，避免用户误解。
- 明确说明日历会自动聚合冲煮记录，但照片和备注需要用户主动添加。
- 明确说明内置做法和自定义做法的区别。
- 明确说明统计页面的数据来源。

## 五、截图制作和维护计划

### 截图原则

- 使用开发分支最新代码。
- 使用专门的演示账号或脱敏数据。
- 不在截图中出现真实邮箱、密码、数据库地址或私密信息。
- 默认使用中文界面。
- 桌面截图统一使用 `1440x900`。
- 移动截图统一使用 `390x844`。
- 每张截图包含一个明确的操作目标，不截图无关区域。
- 截图文件使用稳定英文名称，避免因为文案变化导致路径频繁变更。

至少制作以下截图：

- 登录页。

- 库存列表。
- 无豆种时的新建批次引导。

7. 如果 UI 或操作流程改变，只替换受影响图片。
