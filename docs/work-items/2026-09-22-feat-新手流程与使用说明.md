## 2. 背景

Coffee Lab 的业务流程存在明确的数据前置关系：

~~~text
豆种档案 → 购买批次 → 可用库存 → 冲煮记录 → 日历和统计
~~~

原有页面允许用户在没有前置数据时直接进入后续表单。新用户不知道应该先创建什么，进入表单后才发现无法保存，造成流程中断和错误理解。

## 3. 当前问题或用户需求

### 3.1 Bug 复现：无豆种仍可新建批次

1. 使用没有豆种档案的账号进入 /inventory。
2. 点击“新增批次”，或直接打开 /inventory/new。
3. 页面显示批次表单，但没有可选择的豆种。
4. 用户填写其他字段后，无法完成有效保存。

### 3.2 同类 Bug：无可用库存仍可新建冲煮

1. 使用没有库存批次，或只有 pending/resting 批次的账号进入 /brews/new。
2. 页面进入冲煮表单。
3. 用户无法选择可冲煮批次，最终无法完成有效记录。

### 3.3 产品需求

- 入口层就提示前置条件，减少无效点击。
- 表单层继续保护，防止直接访问 URL 或异常状态绕过入口。
- 用户能够看懂推荐使用顺序，并在任何页面重新查看说明。
- 不使用强制首次登录弹窗，避免用户关闭后找不到说明。

## 4. 用户故事

- 作为第一次使用的用户，我希望知道应该先创建豆种还是批次，以便顺利开始记录。
- 作为没有豆种的用户，我希望点击新增批次时被带到创建豆种，而不是进入无法保存的表单。
- 作为已有豆种的用户，我希望创建豆种后自动回到批次表单并选中刚创建的豆种。
- 作为老用户，我希望可以随时打开使用说明，而不是只能在第一次登录时看到。

## 5. 目标

1. 无豆种时，库存新增入口统一进入创建豆种流程。
2. 创建豆种后自动返回批次表单并预选新豆种。
3. 无可用批次时，所有新增冲煮入口都显示明确引导。
4. Dashboard 展示动态的四步开始使用卡。
5. Layout 提供桌面端和移动端的全局使用说明入口。
6. 保持现有数据模型、RLS、Storage、Auth 和库存扣减逻辑不变。

## 6. 不在范围内

- 不新增数据库表或 migration。
- 不修改 RLS、Storage、Auth 配置。
- 不改变库存状态枚举和冲煮扣减规则。
- 不做首次登录强制弹窗。
- 不使用 localStorage 保存引导关闭状态。
- 不增加埋点、社区、视频教程或后台帮助内容。
- 不改变 /inventory/new、/brews/new 以外页面的业务数据查询。

## 7. 当前行为与目标行为

| 场景 | 当前行为 | 目标行为 |
| --- | --- | --- |
| 无豆种点击新增批次 | 进入无法选择豆种的表单 | 进入 /beans/new?returnTo=/inventory/new |
| 直接访问无豆种的批次表单 | 可以看到空表单 | 展示前置空状态和创建豆种入口 |
| 创建豆种后 | 返回列表或固定页面 | 返回 /inventory/new?bean=<新豆种 ID> 并预选 |
| 无可用批次新增冲煮 | 进入无法完成的表单 | 展示先创建批次的引导 |
| 首页新用户 | 只有零散快捷操作 | 显示豆种、批次、冲煮、日历四步 |
| 查看使用说明 | 没有统一入口 | 侧栏和移动端菜单均可打开帮助面板 |

## 8. 页面和用户流程

### 8.1 批次流程

1. 用户从库存或首页点击新增批次。
2. 页面读取当前用户是否存在豆种档案。
3. 无豆种时进入 /beans/new?returnTo=/inventory/new。
4. 用户保存豆种档案。
5. BeanForm 只接受内部固定的 returnTo=/inventory/new。
6. 创建成功后跳转到 /inventory/new?bean=<新豆种 ID>。
7. BatchForm 读取 bean 参数并自动选中。
8. 用户补充购买批次信息并保存。

returnTo 只允许内部固定路径 /inventory/new，不接受任意外部 URL，避免开放重定向。

### 8.2 冲煮流程

1. 用户从首页、冲煮列表或日历点击新增冲煮。
2. 页面查询状态为 ready 或 in_use 的批次。
3. 没有可用批次时展示先准备库存说明。
4. 用户可返回库存或创建批次。
5. 存在可用批次时才渲染冲煮表单。
6. 提交前再次校验 batch_id，作为第二层保护。

### 8.3 首页步骤卡

固定顺序：

1. 创建豆种档案。
2. 记录购买批次。
3. 记录一次冲煮。
4. 在日历中复盘并补充照片。

状态规则：

- 没有豆种：第一步可操作，其余步骤锁定。
- 有豆种但没有批次：第二步可操作，后续锁定。
- 有可用批次但没有冲煮：第三步可操作，第四步可操作。
- 有冲煮记录：步骤卡转为简化完成状态，但帮助入口仍保留。
- 已完成步骤显示完成状态，不能错误地覆盖后续可操作状态。

### 8.4 使用说明面板

内容必须说明：

- 产品解决什么问题。
- 豆种档案和购买批次的区别。
- 推荐使用顺序。
- 什么时候记录冲煮。
- 日历如何聚合冲煮记录。
- 如何添加当天照片和备注。
- 库存状态和养豆倒计时的含义。

关闭方式：

- 关闭按钮。
- 点击遮罩。
- 按 Escape。
- 手机屏幕内正文独立滚动。

## 9. 字段、状态和业务规则

- 豆种档案是购买批次的前置实体。
- 购买批次必须关联 bean_profile_id。
- 只有 ready 和 in_use 批次可以用于新建冲煮。
- BatchForm 即使从异常 URL 进入，也必须校验 bean_profile_id。
- BrewForm 即使从异常 URL 进入，也必须校验可用批次。
- returnTo 只允许 /inventory/new。
- 所有新增用户可见文案必须通过 t() 获取。
- 步骤卡不使用 localStorage 持久化。

## 10. 交互和视觉要求

- 中文为默认语言，英文切换后步骤和帮助内容完整切换。
- 深色模式下弹窗、遮罩、正文和按钮保持可读。
- 桌面端帮助入口位于侧栏语言/主题控制附近。
- 移动端帮助入口位于移动菜单，避免顶部按钮过密。
- 空状态必须解释原因，并提供下一步操作。
- 加载状态不得显示误导性的可提交空表单。
- 手机视口下帮助面板不能超出屏幕，正文可滚动。

## 11. 技术方案

- InventoryList 读取豆种档案状态并生成新增入口。
- BeanForm 解析并限制 returnTo，创建成功后携带新豆种 ID 返回。
- BatchForm 在无豆种时提前返回空状态，不渲染无效表单。
- BrewForm 只加载 ready/in_use 批次，无可用批次时提前返回引导。
- Dashboard 并行读取豆种、批次和冲煮数据，计算步骤状态。
- 新增可复用组件 src/components/UsageGuide.tsx。
- Layout 管理帮助面板开关和 Escape 事件。
- 服务层继续使用现有查询和 RLS，不新增数据库接口。

## 13. 兼容性和迁移方案

- 有豆种用户的原有批次流程保持不变。
- 有 ready/in_use 批次用户的原有冲煮流程保持不变。
- 直接访问旧路由仍可打开页面，但会得到明确的前置状态。
- 历史批次、冲煮记录和日历记录不受影响。
- Web 与小程序暂不共享此 UI 实现。

## 14. 风险与回滚方案

| 风险 | 影响 | 预防 | 回滚 |
| --- | --- | --- | --- |
| 返回参数导致错误跳转 | 用户无法回到批次表单 | 白名单限制 returnTo | 移除自动返回逻辑 |
| 步骤判断与数据库数据不同步 | 首页状态显示错误 | 使用现有查询结果计算 | 暂时隐藏步骤卡 |
| 移动端弹窗超出屏幕 | 帮助内容不可读 | 独立滚动和视口验证 | 恢复固定高度面板 |
| 空状态阻断老用户入口 | 已有用户无法继续使用 | 按豆种/批次实际状态判断 | 保留表单入口并加强提交校验 |
