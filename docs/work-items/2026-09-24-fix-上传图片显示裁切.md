## 2. 背景和问题摘要

豆种、配方和日历已支持上传图片，但详情、编辑预览和缩略图普遍使用固定横向容器与 object-cover。竖长包装图和手机照片会被上下大幅裁切，用户无法看清包装文字、标签和拉花主体。

## 3. 复现环境

- URL/页面：豆种列表/详情/编辑、配方列表/详情/编辑、日历月视图和当天详情
- 账号类型：有图片数据的登录用户
- 浏览器和版本：现代桌面及手机浏览器
- 视口：390x844、1440x900
- 语言/主题：中英文、浅色和深色
- 数据前置条件：上传 9:16 或 3:4 的竖图

## 4. 复现步骤

1. 给豆种、配方或日历当天记录上传竖长图片。
2. 打开对应列表、详情或编辑页面。
3. 查看固定横向图片容器。
4. 观察图片顶部和底部被 object-cover 裁掉。

## 5. 预期结果

- 详情主图、编辑预览和日历当天大图完整显示。
- 列表与日历月格保持稳定尺寸，并针对竖图采用完整显示。
- 详情图片可以点击进入全屏查看，多图可切换。

## 6. 实际结果

- 详情相册使用 16:9 + object-cover。
- 豆种列表使用固定 h-32 + object-cover。
- 配方列表使用 16:10 + object-cover。
- 编辑预览、相册缩略图和日历图片也使用 object-cover。
- 竖图的关键内容被裁切，且没有查看完整原图的入口。

- 受影响页面：豆种、配方和日历
- 是否影响数据正确性：否

## 8. 根因分析

上传压缩逻辑会等比例缩放，不会裁切原图。裁切发生在展示层：多个页面使用固定横向容器，并统一给 img 设置 object-cover。系统没有根据图片自然宽高选择 object-fit，也没有全屏查看组件。

## 9. 修复方案

### 目标行为

- 新增自适应图片组件：竖图 contain，横图和方图 cover。
- 详情和编辑预览始终 contain。
- 豆种和配方列表图片容器统一为 4:3。
- 详情主图移动端为方形，sm 以上为 4:3。
- 日历月格保持固定高度，当天大图完整显示。
- 豆种、配方详情及日历大图支持全屏查看。

### 技术方案

- 新增 AdaptiveImage，读取 naturalWidth/naturalHeight 判断方向。
- 新增 ImageLightbox，支持关闭、前后切换、键盘和滚动锁定。
- ImageGallery 集成完整显示和 Lightbox。
- 列表和日历缩略图接入 adaptive 模式。
- ImageManager 预览改为 contain。

### 不在范围内

- 不增加手动裁切、焦点位置和图片编辑。
- 不修改上传压缩规则。
- 不修改数据库、RLS、Storage 或 Auth。
- 不重新处理已有图片。
