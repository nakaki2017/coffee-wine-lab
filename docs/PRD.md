# 液体风味公式 产品 PRD

版本：1.1
形态：Web App
默认语言：中文
英文品牌：Coffee Lab
中文品牌：液体风味公式

## 0. 文档摘要

液体风味公式是一个面向咖啡爱好者的个人咖啡管理工具。

它要解决的不是“怎么冲一杯咖啡”这么单点的问题，而是把用户长期喝咖啡过程中分散的数据串起来：

```text
豆种档案 -> 购买批次 -> 养豆 / 库存 -> 冲煮记录 -> 杯测结果 -> 日历回看
```

MVP 的重点是：

1. 管理用户买过的咖啡豆。
2. 记录同一支豆子的多次购买批次。
3. 根据烘焙日期和推荐养豆天数提醒用户什么时候适合开。
4. 记录冲煮参数、评分、备注和杯测结果。
5. 用日历快速看到每天喝了什么，以及当天的拉花 / 咖啡照片。

MVP 不做社区、不做商城、不做 AI 自动杯测、不做微信小程序。

### 配方库分类规则

配方库在同一个页面提供两个小入口：冲煮做法和咖啡饮品。冲煮做法面向 V60、Origami、法压、Espresso 和冷萃浸泡等方法，使用完整冲煮参数；咖啡饮品面向美式、拿铁、冷萃饮品等成品，使用饮品类型、原料和制作步骤，不要求器具、水温、粉量、液量、比例或时间。

冷萃允许同时保存为两条不同记录：一条是冲煮入口下的“冷萃浸泡法”，另一条是饮品入口下的“冷萃”。内置配方维护中文和英文名称，用户自定义配方只维护一个名称；界面切换语言不会自动翻译用户输入内容。

## 1. 产品定位

### 1.1 一句话定位

一个给咖啡爱好者用的咖啡豆库存、冲煮复盘和咖啡日历工具。

### 1.2 产品目标

让用户不用再在表格、备忘录、聊天记录、相册之间来回找咖啡信息。

产品需要帮助用户回答这几个问题：

1. 我现在有哪些豆子？
2. 哪些豆子还在养豆？哪些可以开了？
3. 这包豆子什么时候买的？多少钱？还剩多少？
4. 上次冲得好喝的参数是什么？
5. 我实际喝到的风味和官方描述是否一致？
6. 今天喝了什么？拉花长什么样？

### 1.3 产品调性

1. 工具优先，不做内容社区。
2. 记录要快，回看要清楚。
3. 数据结构要完整，但界面不要显得像会计软件。
4. 对新手友好，对进阶玩家也不拦着。
5. 默认中文，保留英文。

## 2. 目标用户

### 2.1 核心用户

| 用户类型        | 典型行为                                   | 核心需求                       |
| --------------- | ------------------------------------------ | ------------------------------ |
| 家庭手冲用户    | 经常买不同产地、处理法、烘焙度的豆子       | 管理豆子、记录冲煮、复盘参数   |
| 意式 / 拿铁用户 | 关注豆子开封时间、粉量、萃取时间、拉花照片 | 管理库存、记录配方、日历看照片 |
| 轻度专业玩家    | 会比较官方风味和实际杯测结果               | 结构化杯测、风味标签、统计     |
| 复购型用户      | 同一支豆子会反复购买                       | 区分豆种档案和购买批次         |

### 2.2 非目标用户

1. 只喝连锁咖啡，不自己买豆。
2. 不愿意记录任何参数。
3. 主要想社交分享、发笔记、看别人内容。
4. 想直接买豆、下单、支付、查物流的人。

### 2.3 用户成熟度分层

| 成熟度 | 用户状态                         | 产品要怎么服务                     |
| ------ | -------------------------------- | ---------------------------------- |
| 入门   | 只知道豆名、品牌和大概味道       | 表单不要吓人，非必填字段可跳过     |
| 进阶   | 关注粉水比、水温、研磨、养豆     | 提供完整参数字段和复盘入口         |
| 发烧   | 关注杯测维度、风味标签、统计趋势 | 提供杯测雷达图、标签对比和统计视图 |

## 3. 问题定义

### 3.1 用户现在的问题

1. 豆子信息散。

   - 购买链接在聊天里。
   - 风味描述在商品详情页。
   - 烘焙日期在包装袋上。
   - 冲煮参数在备忘录里。
   - 拉花照片在相册里。
2. 同一支豆子多次购买后很难区分。

   - 用户需要知道“这支豆子”是什么，也需要知道“这一次买的这包”是什么。
   - 表格里经常会把豆种和购买批次混成一行，后续统计会乱。
3. 养豆期容易忘。

   - 用户知道豆子要养，但不一定每天记得哪包可以开。
   - 开太早和放太久都会影响体验。
4. 冲煮复盘缺少闭环。

   - 只记录参数，不记录杯测，无法判断是否好喝。
   - 只记录感受，不记录参数，无法复现。
5. 每日咖啡记忆没有入口。

   - 用户会拍拉花或咖啡照片，但照片和当天喝的豆子没有关联。
   - 想回看“这个月我喝了什么”时，相册并不够用。

### 3.2 产品要解决的问题

液体风味公式要建立一套个人咖啡数据结构。

不是为了记录而记录，而是为了让用户能复盘：

1. 哪包豆子好喝？
2. 好喝是因为豆子本身、养豆时间、冲煮参数，还是当天发挥？
3. 哪些豆子值得复购？
4. 哪些做法适合哪些豆子？
5. 每天喝咖啡这件事，能不能被轻量地保存下来？

## 4. 现有解决方案与不足

| 方案              | 用户怎么用                 | 优点                 | 不足                                    |
| ----------------- | -------------------------- | -------------------- | --------------------------------------- |
| 备忘录            | 每次手动写豆子和参数       | 快、无门槛           | 不结构化，后续无法筛选和统计            |
| 表格              | 建字段记录豆子、价格、参数 | 自由度高，可统计     | 移动端体验差，图片和日历弱              |
| Notion / Airtable | 自建数据库                 | 可定制，适合重度用户 | 搭建成本高，流程不是为咖啡设计          |
| 手机相册          | 保存拉花照片               | 视觉回忆强           | 看不到豆子、参数、评分                  |
| 专业咖啡 App      | 记录冲煮和设备             | 参数完整             | 可能过重，不一定适合中文 Web 和个人库存 |

## 5. 竞品调研

本节重点看两类产品：

1. 咖啡冲煮记录工具。
2. 类似“库存 + 配方 + 日历 / 复盘”的工具。

### 5.1 竞品总览

| 产品                     | 类型               | 核心定位                                       | 和我们的关系                                 |
| ------------------------ | ------------------ | ---------------------------------------------- | -------------------------------------------- |
| Beanconqueror            | 咖啡冲煮记录 App   | 高度可定制的咖啡记录、设备连接、统计           | 最接近的专业咖啡记录竞品                     |
| Filtru                   | 咖啡冲煮指导 App   | 多种冲煮方法、计时、蓝牙秤反馈、咖啡豆 Journal | 适合借鉴新手引导和冲煮过程体验               |
| Aeromatic                | AeroPress 垂直 App | AeroPress 配方、计时、自建 recipe、豆子记录    | 适合借鉴“配方库 + 步骤化”体验              |
| Brewfather               | 酿造工具 Web/App   | 配方、批次、库存、成本、设备集成               | 非咖啡，但“配方 + 批次 + 库存”结构值得参考 |
| Notion / Airtable / 表格 | 通用数据库         | 用户自建个人咖啡系统                           | 最大替代方案，不是直接竞品                   |
| Apple Notes + Photos     | 通用记录 / 相册    | 随手记、随手拍                                 | 用户最容易继续使用的低成本方案               |

### 5.2 Beanconqueror

官网信息显示，Beanconqueror 覆盖 brew overview、brew details、statistics、蓝牙设备连接、智能秤曲线、咖啡豆追踪、烘焙管理、水质参数、30+ 冲煮参数、消费和花费统计等能力；它还强调开源、免费、本地离线数据和高度可定制。

【优势】

1. 参数非常完整。
2. 支持智能秤、压力设备、温度设备、折光仪等硬件。
3. 对发烧友友好。
4. 有统计能力。
5. 开源和免费降低用户信任门槛。

【不足 / 机会】

1. 功能很重，新用户可能不知道从哪里开始。
2. 偏原生 App 和本地数据，Web 多端协作不是它的重点。
3. 同步和账号体系不是其近期重点，官网 FAQ 也提到登录 / 同步会带来大量开发和基础设施成本。
4. 它解决“专业记录”很强，但不强调“每天喝了什么 + 拉花照片日历”。
5. 中文用户的默认体验和本土化表达仍有机会。

【我们借鉴】

1. 豆子、冲煮、统计三块必须形成闭环。
2. 参数字段要允许进阶扩展，但 MVP 不追求 30+ 字段。
3. 统计要围绕用户真实问题：花了多少钱、什么器具常用、哪类处理法评分高。

【我们不跟】

1. MVP 不做蓝牙秤。
2. MVP 不做折光仪、压力曲线、水质参数。
3. MVP 不做完全离线本地 App。

### 5.3 Filtru

Filtru 的定位更偏“帮助用户冲出一杯好咖啡”。官网强调 15 种冲煮方法、Espresso 工具、AR 教程、咖啡豆 Journal、蓝牙秤实时反馈、Siri Shortcuts 自动化；也有 espresso 记录、研磨建议、萃取计算、流速和注水目标反馈。

【优势】

1. 对新手友好。它会告诉用户下一步怎么做。
2. 冲煮过程体验强，尤其是计时、注水目标、蓝牙秤反馈。
3. Espresso dial-in 能力比普通记录工具更强。
4. 视觉和动效更偏消费级 App。

【不足 / 机会】

1. 更像“冲煮助手”，不是完整的个人咖啡资产管理。
2. 咖啡豆 Journal 有价值，但同一豆子的多次购买、库存状态、养豆提醒不是核心。
3. 日历照片回看不是主线。
4. 对中文用户和 Web 使用场景仍有空间。

【我们借鉴】

1. 做法模板要能直接带入冲煮记录。
2. 新手可以先从 recipe 开始，不必理解所有字段。
3. 后续可以考虑“建议调整研磨 / 粉量”，但 MVP 先不做。

【我们不跟】

1. MVP 不做 AR 教程。
2. MVP 不做蓝牙秤实时流速反馈。
3. MVP 不做 Siri Shortcuts。

### 5.4 Aeromatic

Aeromatic 是一个 AeroPress 垂直工具。官网强调 60+ curated recipes、分步说明、内置秒表、视频 walkthrough、自建 recipes、记录 notes 和 tracking coffee beans。

【优势】

1. 单一器具定位清楚。
2. 配方库价值强。
3. 适合用户试不同 AeroPress 做法。
4. 分步说明和计时降低操作门槛。

【不足 / 机会】

1. 器具范围窄，主要围绕 AeroPress。
2. 更偏 recipe / timer，不是完整库存管理。
3. 不解决多种冲煮方式、多批次购买、日历照片复盘。

【我们借鉴】

1. “做法库”可以降低记录门槛。
2. 内置模板不需要很多，关键是可复用。
3. 配方步骤应该结构化保存，而不是只是一段说明文字。

【我们不跟】

1. MVP 不做视频教程。
2. MVP 不围绕单一器具做垂直产品。

### 5.5 Brewfather

Brewfather 是啤酒酿造工具，不是咖啡 App。但它非常值得参考。官网强调 recipe 管理、batch details、ingredients inventory、batch tracking、inventory management、cost tracking、浏览器和移动端、多设备、离线、自动同步、设备集成等。

【为什么要看它】

咖啡和啤酒不同，但它们都有：

1. 配方。
2. 批次。
3. 原料 / 库存。
4. 成本。
5. 过程记录。
6. 复盘。

【优势】

1. “配方 + 批次 + 库存 + 成本”结构完整。
2. Web + App 多端形态成熟。
3. 数据管理能力强。
4. 对重度用户的批次跟踪很清楚。

【不足 / 机会】

1. 产品对象是啤酒酿造，不适合直接迁移到咖啡用户。
2. 对咖啡的养豆、拉花照片、杯测风味没有直接解决。
3. 信息密度较高，咖啡 MVP 不应一开始做得这么重。

【我们借鉴】

1. 批次是核心对象，不能只做“豆子”。
2. 成本和库存要从第一版就有字段。
3. 后续若做更复杂库存，应该学习它的 batch tracking 思路。

### 5.6 Notion / Airtable / 表格

这是最真实的替代方案。

很多用户不会下载咖啡 App，而是自己建表：

1. 豆名。
2. 品牌。
3. 价格。
4. 烘焙日期。
5. 风味。
6. 冲煮参数。
7. 评分。

【优势】

1. 完全自由。
2. 用户熟悉。
3. 可导出。
4. 可以随便加字段。

【不足 / 机会】

1. 手机端新增记录很慢。
2. 图片、日历、状态流转体验差。
3. 养豆提醒要自己写公式。
4. “豆种”和“购买批次”关系需要用户自己设计。
5. 统计需要用户自己搭。

【我们借鉴】

1. 字段不要太死。
2. 未来要支持导出，降低用户迁移焦虑。

【我们不跟】

1. 不做无限自定义字段。
2. 不把 MVP 做成数据库搭建工具。

### 5.7 Apple Notes + Photos

这是最低成本的现有方案。

用户随手记一段文字，再拍一张照片。没有学习成本。

【优势】

1. 快。
2. 所有人都会用。
3. 照片回看自然。

【不足 / 机会】

1. 无结构化数据。
2. 无库存和养豆状态。
3. 无冲煮参数统计。
4. 无豆种、批次、冲煮之间的关联。

【我们借鉴】

1. 日历和照片入口要足够轻。
2. 用户不想每次都填完整表单，所以当天备注和照片要能快速保存。

## 6. 竞品结论

### 6.1 市场空位

现有工具大致分两类：

1. 专业冲煮记录：参数完整，但偏重。
2. 通用记录工具：自由，但不懂咖啡。

液体风味公式的机会在中间：

```text
比表格更懂咖啡
比专业硬件 App 更轻
比相册更结构化
比做法计时器更长期
```

### 6.2 差异化 USP

1. 豆种和购买批次分离。

   - 同一种豆子可以多次购买。
   - 每次购买可以记录价格、时间、重量、状态和剩余量。
2. 养豆和库存是主链路，不是附属字段。

   - 用户打开首页就能看到哪些在喝、哪些可开、哪些还在养。
3. 冲煮和库存联动。

   - 新增冲煮后自动扣剩余量。
4. 杯测复盘不只是评分。

   - 记录多个感官维度。
   - 对比官方风味和用户实际感受。
5. 咖啡日历是核心体验。

   - 每天看喝了什么。
   - 每天看拉花 / 咖啡照片。
   - 这个点和大多数冲煮工具不一样。
6. 中文默认的 Web App。

   - 不依赖小程序。
   - 以后可以直接通过域名访问。

## 7. 产品范围

### 7.1 MVP 做什么

MVP 要完成一条完整闭环：

```text
注册登录
  -> 添加豆种
  -> 创建购买批次
  -> 查看养豆 / 库存状态
  -> 记录冲煮
  -> 记录杯测
  -> 日历回看
  -> 基础统计
```

### 7.2 MVP 功能清单

| 模块     | 功能                                    | 优先级 | 说明                   |
| -------- | --------------------------------------- | ------ | ---------------------- |
| 账号     | 注册、登录、鉴权保护                    | P0     | 个人数据必须隔离       |
| 国际化   | 中文默认、英文切换                      | P0     | 品牌中文为液体风味公式 |
| 豆种档案 | 新增、编辑、搜索、详情                  | P0     | 记录豆子的稳定信息     |
| 购买批次 | 新增、编辑、状态、价格、重量、剩余量    | P0     | 记录每次购买           |
| 养豆提醒 | 根据烘焙日 + 推荐养豆天数显示可开封时间 | P0     | 首页和批次详情体现     |
| 冲煮记录 | 参数、设备、评分、备注、注水方案        | P0     | 关联批次               |
| 库存扣减 | 新增冲煮后按粉量扣减剩余量              | P0     | 最低为 0               |
| 杯测记录 | 感官维度、总分、风味标签、对比备注      | P1     | 用于复盘               |
| 做法模板 | 内置做法、自定义做法、从做法创建冲煮    | P1     | 降低记录门槛           |
| 日历     | 月视图、当天冲煮、照片、备注            | P0     | 作为咖啡日记           |
| 统计     | 花费、均价、评分、品牌、器具、趋势      | P1     | 先做基础分析           |

### 7.3 MVP 不做什么

1. 不做微信小程序。
2. 不做 WebView 嵌入小程序。
3. 不做社区、关注、评论、点赞、Feed。
4. 不做商城、下单、支付、优惠券。
5. 不做咖啡豆价格自动抓取。
6. 不做 AI 自动杯测。
7. 不做 AI 图片识别拉花。
8. 不做蓝牙秤、压力计、折光仪等硬件连接。
9. 不做 AR 教程、视频教程。
10. 不做复杂库存流水和自动回滚。
11. 不做团队协作和共享库存。
12. 不做离线模式。
13. 不做原生 App。

## 8. 信息架构与页面清单

### 8.1 导航结构

| 页面        | 路由           | 作用                           |
| ----------- | -------------- | ------------------------------ |
| 登录 / 注册 | `/auth`      | 账号入口                       |
| 首页        | `/`          | 库存状态、养豆倒计时、最近冲煮 |
| 豆种档案    | `/beans`     | 管理所有咖啡豆基础信息         |
| 库存        | `/inventory` | 管理购买批次和状态             |
| 冲煮记录    | `/brews`     | 管理所有冲煮                   |
| 配方库      | `/recipes`   | 浏览内置配方和管理私有配方     |
| 配方详情    | `/recipes/:id` | 查看图片、原料、参数和制作步骤 |
| 日历        | `/calendar`  | 按天回看喝了什么和照片         |
| 统计        | `/stats`     | 总览消费、评分和使用习惯       |

### 8.2 页面目标

【首页 Dashboard】

- 让用户一打开就知道当前有什么豆子可喝、什么豆子还在养、最近喝了什么。

【豆种档案】

- 保存“这支豆子是什么”。
- 不直接代表一次购买。
- 可保存包装、标签等最多 3 张图片，并选择封面。

【库存 / 批次】

- 保存“这一次买的这包豆子是什么状态”。
- 这是购买时间、金额、重量、剩余量、养豆状态的归属地。

【冲煮记录】

- 保存“这一次怎么冲”。
- 它必须关联到某个购买批次。

【配方库】

- 保存可复用的冲煮做法和咖啡饮品配方。
- 内置配方对登录用户可见，用户配方仅本人可见。
- 配方不是一次实际冲煮或饮品制作记录。

【日历】

- 保存“今天喝了什么”和“今天照片是什么样”。
- 允许用户不填完整冲煮，也能留下当天备注和图片。

【统计】

- 帮用户看到长期偏好和消费。

## 9. 核心用户流程

### 9.1 首次建档流程

```text
注册 / 登录
  -> 新增豆种档案
  -> 新增购买批次
  -> 首页出现库存状态
```

验收：

1. 用户能在 3 分钟内完成第一支豆子的建档。
2. 只有品牌、豆名、重量等关键字段必填，其他信息可以后补。

### 9.2 买豆入库流程

```text
库存
  -> 新增批次
  -> 搜索并选择豆种
  -> 填购买日期 / 烘焙日期 / 价格 / 重量
  -> 保存
  -> 批次出现在库存列表
```

关键规则：

1. 若用户是复购同一豆种，仍然创建新的批次。
2. `bean_profile` 不重复承载购买信息。
3. 剩余量默认可以等于购买重量。

### 9.3 养豆提醒流程

```text
批次有 roast_date
  + 豆种有 recommended_resting_days
  -> 系统计算 ready_date
  -> 首页 / 库存 / 批次详情展示
```

公式：

```text
ready_date = roast_date + recommended_resting_days
```

### 9.4 冲煮记录流程

```text
冲煮记录
  -> 新建冲煮
  -> 选择批次
  -> 选择器具 / 填参数 / 评分 / 备注
  -> 保存
  -> 扣减批次剩余量
```

扣减规则：

```text
new_remaining = max(0, old_remaining - dose_grams)
```

这里要注意：

- MVP 只在新增冲煮时扣库存。
- 编辑 / 删除冲煮暂不回滚库存。
- 后续若要做回滚，必须引入库存流水。

### 9.5 杯测流程

```text
冲煮详情
  -> 添加杯测
  -> 记录感官维度
  -> 添加风味标签
  -> 对比官方风味
```

目标：

1. 不是做专业 SCA 表。
2. 是让个人复盘可比较。

### 9.6 日历流程

```text
日历
  -> 选择日期
  -> 查看当天冲煮
  -> 上传 / 粘贴图片
  -> 写当天备注
  -> 保存
```

日历的意义：

- 它不是统计图。
- 它是一个“咖啡记忆入口”。
- 用户可以快速看到这个月喝了什么，也能看到拉花进步。

## 10. 核心功能需求

### 10.1 豆种档案

字段：

- 品牌
- 烘焙商
- 咖啡豆名称
- 产地国家
- 产区
- 处理法
- 品种
- 海拔
- 烘焙度
- 推荐养豆天数
- 购买链接
- 最多 3 张图片，首张为封面
- 历史图片 URL
- 风味描述

规则：

1. 豆种档案代表稳定信息。
2. 同一种豆子复购时，不新增豆种，新增批次。
3. 删除豆种前，需要检查是否存在活跃批次。
4. 每张上传图片压缩到 800KB 内；最多 3 张，支持排序和设为封面。
5. 用户只能读取和维护自己的豆种图片。

### 10.2 购买批次 / 库存

字段：

- 关联豆种
- 批次编号
- 状态
- 购买日期
- 烘焙日期
- 到手日期
- 开封日期
- 价格
- 重量
- 剩余量
- 购买渠道
- 是否复购
- 备注

状态：

```text
pending -> resting -> ready -> in_use -> finished -> archived
```

规则：

1. 状态可以手动推进。
2. 状态推进到 `in_use` 时，若没有开封日期，可自动填当天。
3. `ready` 不等于已经开封。
4. `finished` 表示喝完。
5. `archived` 表示不再参与日常使用。

### 10.3 冲煮记录

字段：

- 批次
- 做法
- 冲煮时间
- 器具
- 研磨刻度
- 水温
- 粉量
- 液量
- 比例
- 总时间
- 注水方案
- 滤纸类型
- 杯数
- 评分
- 备注

规则：

1. 冲煮必须关联批次。
2. 批次必须来自当前用户。
3. 新增冲煮后扣减库存。
4. 从做法创建冲煮时，默认参数应带入表单。
5. 从日历新增冲煮时，日期应带入表单。

### 10.4 杯测记录

字段：

- 香气
- 酸质
- 甜感
- 苦感
- 醇厚度
- 余韵
- 干净度
- 平衡感
- 整体评分
- 风味标签
- 对比备注

规则：

1. 一条冲煮最多维护一条杯测记录。
2. 有官方风味描述时，展示匹配和额外标签。
3. 标签可以来自系统预置，也可以用户手动输入。

### 10.5 咖啡配方库

字段：

- 名称
- 器具
- 默认研磨
- 默认水温
- 默认粉量
- 默认液量
- 默认比例
- 默认时间
- 默认注水方案
- 默认滤纸
- 步骤说明
- 配方类型：冲煮做法 / 咖啡饮品
- 原料、用量和单位
- 结构化制作步骤
- 最多 5 张配方图片

规则：

1. 系统可提供内置做法。
2. 用户可创建自己的做法。
3. 内置做法不能被用户直接覆盖。
4. 用户可以复制内置做法再编辑。
5. 用户创建的配方默认私有，其他用户不可查看。
6. 内置配方只允许通过受控发布流程维护，普通用户不可修改或删除。
7. 冲煮做法可以带入冲煮表单；咖啡饮品首期只保存和查看，不扣减咖啡豆库存。
8. 每张图片压缩到 800KB 内，首张为封面，最多 5 张。

### 10.6 咖啡日历

字段：

- 日期
- 图片 URL
- 当天备注
- 当天冲煮记录列表

规则：

1. 同一用户同一天最多一条 daily entry。
2. 当天冲煮从 `brew_records.brew_date` 聚合。
3. 当天照片来自 `daily_entries.image_url`。
4. 图片上传 MVP 使用 Supabase Storage。
5. 用户也可以先粘贴图片 URL。

### 10.7 统计

MVP 统计项：

1. 总花费。
2. 批次数。
3. 平均每 100g 价格。
4. 平均评分。
5. 最常购买品牌。
6. 器具使用占比。
7. 不同处理法平均评分。
8. 评分分布。
9. 冲煮趋势。
10. 水温与评分关系。
11. 复购最多豆子。

## 11. 成功指标

### 11.1 MVP 可用性指标

1. 新用户能完成第一条豆种 + 第一条批次。
2. 用户能在移动端完成一次冲煮记录。
3. 用户能在日历中看到当天冲煮。
4. 用户能保存当天照片或图片 URL。

### 11.2 留存指标

1. 7 天内是否创建第二条冲煮记录。
2. 30 天内是否创建第二个购买批次。
3. 30 天内是否打开日历 3 次以上。
4. 是否存在复购批次。

### 11.3 数据质量指标

1. 有烘焙日期的批次占比。
2. 有评分的冲煮记录占比。
3. 有杯测记录的冲煮占比。
4. 有照片的日历日期占比。

## 12. 技术与成本口径

### 12.1 技术方案

当前技术栈：

- Vite
- React
- TypeScript
- Tailwind
- Supabase Auth
- Supabase Database
- Supabase Storage

详细开发约束见 `ARCHITECTURE.md`。

### 12.2 成本判断

MVP 成本可控。

原因：

1. 不做自建后端，直接使用 Supabase。
2. 不做 AI，因此没有推理 API 成本。
3. 不做视频；豆种和配方图片在浏览器端压缩后上传。
4. 用户规模小的时候，数据库和认证成本很低。

主要成本风险：

1. 图片存储。
2. 图片流量。
3. 后续如果加 AI 分析，会新增 API 成本。
4. 如果做小程序或备案，会新增时间成本。

## 13. 主要风险

| 风险                | 说明                     | 处理策略                                 |
| ------------------- | ------------------------ | ---------------------------------------- |
| 记录成本过高        | 字段太多，用户懒得填     | 非核心字段可选；支持从做法带入           |
| 产品过专业          | 新手被参数吓退           | 首页和表单保持轻量，先完成主流程         |
| 图片成本失控        | 用户上传大量照片         | 3/5 张上限、800KB 压缩、1MB Bucket 限制 |
| 库存扣减不严谨      | 编辑 / 删除冲煮不回滚    | MVP 明确不做；后续用库存流水解决         |
| 和专业 App 正面竞争 | Beanconqueror 等能力很强 | 不卷硬件连接，主打库存 + 日历 + 中文 Web |
| 和表格竞争          | 用户已经习惯表格         | 提供更低录入成本、更好移动端和日历体验   |

## 14. 验收标准

### 14.1 主流程验收

1. 用户能注册 / 登录。
2. 未登录访问业务页面会跳转登录页。
3. 用户能新增豆种档案。
4. 用户能基于豆种新增购买批次。
5. 用户能看到养豆倒计时和库存状态。
6. 用户能新增冲煮记录并关联批次。
7. 新增冲煮后，批次剩余量正确扣减。
8. 用户能在冲煮详情添加杯测。
9. 用户能创建自定义做法，并从做法带入冲煮。
10. 用户能在日历看到当天冲煮。
11. 用户能在日历日期详情保存照片和备注。
12. 用户能切换中英文。
13. 用户能为豆种维护最多 3 张图片并调整封面。
14. 用户能浏览内置配方、查看详情并复制为自己的私有配方。
15. 用户能创建包含原料、步骤和最多 5 张图片的私有配方。

### 14.2 异常验收

1. 未选择豆种时，不能创建批次。
2. 未选择批次时，不能创建冲煮。
3. 删除有活跃批次的豆种时，应阻止。
4. 图片上传失败时，应提示错误。
5. 数据加载失败时，不应白屏。
6. 空数据页面应有明确引导。

### 14.3 回归验收

1. `npm run typecheck` 通过。
2. `npm run build` 通过。
3. 浅色 / 深色模式均可读。
4. 移动端底部导航可用。
5. 桌面侧边栏可用。
6. Supabase RLS 保证用户只能访问自己的数据。
7. 普通用户不能修改、删除或伪造内置配方。
8. 用户不能读取其他用户的私有配方和图片。
